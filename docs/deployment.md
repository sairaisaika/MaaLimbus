# 出战顺序准备

开发任务「Prepare deployment」只处理当前战斗准备页，完成顺序观察后停止，
不会点击战斗开始按钮。该任务默认关闭，仍需真实准备画面验证位置与标记。

队伍选项沿用保存编号；默认使用已保存的 `deployment` 顺序，无配置就停止。
也可以明确选择「Save natural sinner order」保存标准十二人顺序；自定义顺序
目前可从原有队伍配置读取，完整可视排序编辑器尚未完成。
每场采用当前识别人数上限对应的顺序前缀，不在人数识别失败时猜测上限。

## 原生流程

权限和单控制器检查 → 读取保存队伍 → 保留/保存顺序 → 页面/人数/顺序标记检查 →
按已保存顺序选择下一人 → 新画面验证人数加一且新增对应序号 → 继续。
已选择顺序是目标前缀时可以续选；完整顺序匹配时只保存观察证据。
计数与标记不一致、已有顺序不同、缺配置或资源界面均停止。
一次点击不生效时只重新观察，不重复点击、自动重置或继续启动战斗。

参考固定版本 Lix `431b432e22f0b0da08b95d7c478fa213be20b3e8`
`lalc_backend/task_action/utils.py` 的 `team_order_map` / `ready_to_battle`：

- 参考尺寸 1280×720，十二人两行六列，中心 x=290..940（间隔130），y=240/440。
- 人数原参考区域 `[1130,500,100,50]`。数字是实际观察值，非页面模板。
- 未沿用 OCR 失败默认 0/1、盲点十二人或无后续证据直接确认的操作。

人数使用局部位置与 Details 联合定位；资源、战败及队伍库判定优先。
顺序标记小区域是依据格子中心设计的**实验性识别位置**，不是已经被 Lix 或实机验证的坐标。
整屏检测器会漏掉孤立数字，故这些小区域使用 Maa `only_rec`，完整记录 ROI、文字和置信度。
只有独立 1..12、无重复/漏号、与人数一致时才形成顺序。肖像变化不参与匹配。
当前不处理 11/5 等含义尚未核实的溢出计数，不将其误当作可安全继续的准备状态。

部分续选、已有完整顺序、顺序不符、缺人数、资源弹窗、点击无效、计数增加但标记缺失、无配置。

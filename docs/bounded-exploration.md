# Bounded exploration and review

The player authorized bounded attempts on unfamiliar pages on 2026-10-12.
An unknown scene is not, by itself, an immediate stop. The Mirror runner first
observes loading/animation frames, then tries independently recognized navigation
controls. Header Close/Back/Return requires unique native OCR at .95; the header
arrow requires its native template at .92. Up to three different controls can be
attempted in one unresolved navigation episode. No repeated blind tap is planned.
Each attempted input is reserved before Maa receives it. Restart observes the
successor of that attempt instead of replaying it. Unchanged/unknown results remain
in history; successful independently named successors allow the run to continue.

An already identified gift page can contain a trial outside the finite grammar.
Normally the fully priced choices rank first. Only when these run out does the
separate exploration rank compare the observed enemy level, saved keyword match
and ownership with a declared uncertainty penalty of 1000. This is a heuristic
game choice, not an interpretation of the unread effect or a learned reward.
Titles, counters, scope and gift transaction successors still have to match.
Module/Lunacy/payment text cannot enter this fallback.

Review bundles live under the authoritative data root's parent:
`build/learning-review/transitions/` and `build/learning-review/trials/`.
Each bundle contains original frame JSON, PNG bytes, hashes, the action or printed
trial, a readable trace, a proposal and a separate `review.json` for approval or
correction. An automatic candidate remains `reviewed=False` and
`training_eligible=False`. It does not approve itself as model truth. Unknown
effects remain raw text until a distinct teacher or human correction establishes
their meaning. Resolving navigation does not prove a dungeon clear or payout.

Unresolved purchase/selection/receipt transactions are reconciled by their own
successor rules before exploration. Paid rewards and Enkephalin conversion retain
their scoped budget gates. A scene transition never becomes spending permission.

The same native observation path reads each deployment number with two independent
digit crops at .9. Correct visible order submits directly. Missing digits trigger
bounded re-reading; only a positively inconsistent order requests Clear Selection.
After START, an unidentified combat animation can be observed for up to 120s;
the script neither submits START again nor claims the animation is a victory.

Offline tests exercise these boundaries. Live acceptance still requires the
installed MainTask/GUI Start route and retained actual successor evidence.
